Drawing Review checks a 2D mechanical drawing in [Chat](/overview/core_features/chat).
The DXF file is the source of measurements, units, layers, blocks, and text.
The plotted sheet is the source of the checklist. The two results stay separate.
A comment on the sheet does not replace a DXF measurement.

The review does not certify the drawing. It does not claim ASME, ISO, or company-standard compliance.

## What you upload

Use both files when you have them. You can upload only one.

| File                    | Role                                            |
| ----------------------- | ----------------------------------------------- |
| DXF                     | Measurements, units, layers, blocks, and text   |
| PDF, PNG, JPEG, or WEBP | Title block, views, notes, and the sheet layout |

Export a DWG file to DXF before you upload it. Onyx does not read DWG or STEP files.
The sheet must be the file you plotted. Onyx does not draw the DXF.

## Set up the agent

An admin creates the agent. The default assistant does not include this action.

<Steps>
  <Step title="Create an agent">
    Open **Admin Panel → Agents** and create an agent. Name it Drawing Review.
  </Step>

  <Step title="Add the action">
    Add the **Drawing Review** action. Leave the default system prompt in place.
  </Step>

  <Step title="Attach standards">
    Add a **Document Set** that contains your drawing standards. When the agent has no document set,
    each finding says that no company standard was used.
  </Step>

  <Step title="Write short instructions">
    In the agent instructions, tell the agent to call `review_drawing` and answer with the findings list.
  </Step>
</Steps>

The action uses the [Captioning LLM](/admins/advanced_configs/search_configs) for the sheet.
Set that model under **Admin Panel → Index Settings**. When it is not set,
the DXF result still returns and the sheet section says the model is not configured.

## Read the answer

The answer has two sections.

- **Measured** comes from the DXF. It lists units, layers, blocks, text, and dimension entities.
- **Observed** comes from the plotted sheet. It lists the checklist.

The checklist covers the title block, views and notes, dimensions and tolerances, visible GD&T, BOM and callouts,
and the same fields across sheets. Each item is **Pass**, **Fail**, or **Needs review**. Ask for one group,
such as dimensions, when you do not want the full checklist.

A number in a text note is not a measurement. Only a dimension entity is a measurement.
A mismatch between a dimension entity and text on the sheet is a finding. When you upload only one file,
the answer says which check did not run.

On a wide screen, the sheet is in the center. The chat stays on the right. The checklist is in the chat response.
Select a failed or uncertain finding there. The sheet opens that page and highlights the text the finding uses.
Select the highlight to select the finding. A finding with no text on the page highlights the whole page.
A passed item has no highlight and stays collapsed. On a narrow screen,
the checklist and the sheet stay in the tool card.

Onyx reviews the first 8 pages. The answer names any later pages that were not reviewed.

## Check comments on a new sheet

Use this check when you have a marked-up sheet and a new sheet. The marked-up sheet has the comments.
The new sheet is the revision. The default assistant includes **Comment Review**.
An agent that already has Drawing Review gets this action too.

Ask the agent to verify the changes after you attach both sheets. The first sheet is the marked-up sheet.
The second sheet is the new sheet. You can name features, values, and tolerances to verify. For example,
ask "Only check PDF page 2.
Verify that the bracket width is 130 and skip unrelated issues." The agent passes these instructions to the review with
the two files.

Keep the file roles clear: the original contains review comments, and the revised sheet contains the corrections.
The action rejects likely reversed PDF roles when only the revised input contains native comments.
If no comments can be extracted, the action reports an incomplete review. It does not report a passed drawing.

Attach two PDFs for Before/After review. Prefer PDFs exported from CAD. Scanned PDFs use paired visual checks.
A comment is a cloud, a balloon, a redline, or a note. This check does not accept images or CAD files.
Onyx checks the full original sheet and uses close-ups to help read small colored marks embedded in the page.
A number in a comment is not an independent geometry measurement. It can specify a requested callout value.
A written instruction is optional:
a circled dimension with a clearly associated red replacement number can define a change. For example,
circled **90** with nearby red **80** requests **90 → 80** on that dimension.
A circled overall width **120** with red **100** below requests **120 → 100** on the overall-width dimension.
The reviewer uses close-ups to follow the mark to its target and checks the same feature in the revised PDF.
If a second check rejects an observation, the issue shows the reason for uncertainty. An unexplained circle,
illegible replacement, or uncertain feature match still needs confirmation.
Onyx can check both endpoints of a numbered PDF bracket against the revised dimension lines.
Each issue shows the reason for an unresolved result. A confirmed wrong edit shows the requested and observed values.

Ask the agent to check each comment. The answer has one row per comment.

- **Open.** The new sheet does not satisfy the request. This includes a known mismatch with an unknown original value.
- **Solved, correct.** The requested change is on the new sheet and it matches the comment.
- **Solved, incorrect.** The new sheet changed that area, but the change does not match the comment.
- **Unclear.** The pages do not show enough to decide.

Comment review checks supervisor requests against the revised drawing using the configured **Captioning LLM**.
The same vision model validates local PDF candidates and proposes printed-text or geometry changes the comparison
missed. No second model or result cache is used.

**Printed text changes** lists confirmed printed-text differences.
Expand **Other visual differences** for confirmed geometry changes.
Each finding describes the visible difference in both drawings. Rotation, layout shifts, rendering artifacts,
and review marks are not drawing findings.
New discoveries without native text support need a focused check of both feature regions.
Unchecked and unconfirmed candidates do not appear as findings.

Supported linear dimensions match through their extension-line origins,
even when text rotates or the dimension line moves. Equal values on different references remain separate.
A shorthand comment such as **missing**, **update**,
or a bare value requires evidence for its target and requested action. The reviewer follows marks, arrows, leaders,
and dimension endpoints, then checks the corresponding feature in the revision.
A nearby or repeated value alone cannot verify the request. Ambiguous intent remains **Unclear**.

Verified changes appear on the associated comment card once. Unrelated confirmed changes remain separate.
Select **Show in original** or **Show in revised** to inspect the corresponding source region.
Select **Without a possible comment link** to filter spatial associations.
A possible association does not confirm the requested action. An unlinked difference does not establish a design error.

The reviewer pairs reordered sheets through unique sheet identifiers or sufficiently detailed,
identical native sheet text. It reports inserted, removed, and ambiguous sheets separately.
It does not assume matching page order for unidentified packages. Identity inspection covers at most 64 pages.
Rendering and comparison cover the first eight pages of each PDF.
The result lists actual page pairs and identifies skipped pages. If Onyx compares no sheets,
the review shows incomplete coverage. If the PDFs have the same sheet order and page count,
tell the agent to compare them by page number. Explicit original-page restrictions apply to both checks.
Native PDF review annotations are excluded from the local comparison. Flattened marks still require visual filtering.
Small native numeric edits are checked independently of visual noise filtering.

Check **Comment verification** and **Change validation** separately.
Coverage lists completed pages and incomplete checks. Timeouts, cancellations, pairing failures,
and page limits preserve completed results. **No confirmed differences** requires completed checks.
**Review incomplete** does not establish that the drawings are unchanged. A PDF pair can run once per chat turn.
A new turn can start a fresh review.

Printed text correspondence does not verify CAD feature identity, physical geometry, or engineering correctness.

A clear request needs no complete sentence. Marks can use any color. The reviewer connects a value to its bracket,
leader, or affected callout before comparing the revised feature.
An unreadable original value does not make a readable revised mismatch unclear.
Conflicting comments need clarification unless an explicit instruction establishes their priority.

When native text omits a target, visual evidence receives a separate verification pass.
Unconfirmed observations retain their evidence and the specific reason they remain unclear.
Visual evidence does not create an exact text highlight or establish a CAD measurement.

On a wide screen, one PDF opens beside the conversation. Drag the divider to resize either pane. On smaller screens,
switch between **Conversation** and **Document**. The desktop drawing view starts with the PDF toolbar.
The extra workspace title and layout-reset bar are removed.
Selecting **Show in original** or **Show in revised** opens that revision and page.
A located finding shows a two-second attention ring. Navigation preserves the current zoom.

The review summary filters **All**, **Needs attention**, **Unclear**, and **Addressed** findings.
Search finds text in requests, evidence, and remaining work. Expand a finding for details.
Revision buttons remain available when details are collapsed. Open **Review details** to see the vision model.

The PDF toolbar provides page navigation, zoom, **Annotate**, search, and more actions.
Annotation controls appear when you select **Annotate**. Print, export, rotate, and pan are in the more-actions menu.

The check uses the Captioning LLM. When it is not set, no verdict is invented.
Onyx checks the first 8 pages of each sheet.

## Private Review Queue pilot

The private Review Queue is a separate workflow at `/app/reviews`. It saves reviews outside chat.
Closing the browser does not cancel processing. Each user can read and change only their own reviews in this pilot.
Shared project review and drawing-release approval are not included.

Upload the **Original PDF with comments** and **Revised PDF** separately.
Each PDF must have 1–8 pages and must be at most 20 MiB.
Confirm that both PDFs contain the same sheets in the same order. Different page counts fail validation.
Reordered sheets need correction before upload.

The worker retains native PDF annotations and, when vision is configured,
also scans before-page images for additional graphic or handwritten marks.
Failed visual discovery is reported as incomplete coverage.
A missing private model leaves unsupported comments as **Needs review**.
An exact note replacement check verifies text only. It does not measure geometry.

Select a review to compare the PDFs and their evidence highlights. Record an engineer decision for each proposal,
with an optional reason. The decision history preserves earlier decisions.
**Export Review** downloads the current results and decision history as JSON.
The export includes the original file hashes and processing version. It does not certify or approve the drawing.

### Enable the pilot

Use a backend and web build from this checkout. Released images do not include these changes.
Run the database migration before you enable the feature. The pilot supports single-tenant installations only.

Set these backend settings:

| Variable | Value |
| --- | --- |
| `DEPTH_REVIEW_ENABLED` | `true` enables the API and sidebar entry |
| `DEPTH_REVIEW_API_BASE` | Ollama HTTP(S) origin with a literal internal IP, such as `http://127.0.0.1:11434` |
| `DEPTH_REVIEW_MODEL` | Installed vision model name, validated on your drawing samples |

The review model is independent of the chat model. There is no public-provider fallback. Without both model settings,
native comments remain available for manual checking. The inference origin cannot include credentials, a query,
or a path. In containers, use the inference server's reachable internal address.
Loopback refers to the current container.

Start a separate worker with the same database, file-store settings, and tenant schema as the API:

```bash
PYTHONPATH=backend uv run python -m onyx.engineering.worker
```

For a Lite Compose installation, apply the review overlay last:

```bash
docker compose -f docker-compose.yml -f docker-compose.onyx-lite.yml \
  -f docker-compose.depth-review.yml up -d --build
```

The API applies migrations before serving requests. A worker can retry until the schema is available.
The review worker uses PostgreSQL and does not require Redis or OpenSearch.
Jobs interrupted by worker failure can restart, up to three attempts. An interrupted review restarts its processing;
individual comment checkpoints are not included in this pilot.
**Cancel Review** prevents a late worker from publishing its result.
Cancellation waits for an active parser or model call to return or time out.

### Prepare a private installation

The inference restriction applies to this workflow. It does not change other chat tools or provider settings.
Use customer-approved database and file storage. The Lite profile stores files in PostgreSQL.
Disable unapproved analytics, error reporting, and tracing exporters in the web and API configuration.
Block unapproved outbound traffic and verify the full workflow before claiming offline operation.
The review overlay does not configure a network firewall or prove air-gap support.

Back up the database and file store together. Test that a restored review can open both PDFs.
This pilot has no automated retention or review deletion workflow.
Set an approved retention process before using confidential customer drawings. GPU start/stop automation,
automatic sheet alignment, and validated model benchmarks are future work.

In the private pilot, verification also receives the complete extracted revision-page text.
A definite proposal needs a matching verbatim text excerpt. This check validates the quoted text,
not its engineering interpretation.
The private pilot also returns independent PDF change evidence and coverage messages.
The change comparison does not decide whether a revised design is correct.

The private review adapter requests an 8,192-token Ollama context.
Its input budget and inference-server context use the same limit.

A precise revision highlight requires matching text in the cited span.
Unsupported span references use a page-level highlight instead.

Identical original and revision PDFs are rejected before inference.

## Review PDFs in chat

Attach one or two PDFs to your chat. The drawing viewer opens beside the conversation.
Use the tabs above the viewer to switch between the original and revised PDFs.

Each comment result has a numbered card with its request, evidence, and status.
Select **Show in original** or **Show in revised** to open that PDF at the finding.
A confirmed location uses native PDF annotations. Navigation preserves zoom, opens the target page,
and shows a two-second attention ring. Green indicates a completed correction.
Red indicates an open or incorrect correction. Amber indicates an uncertain result.

There is no hover preview. Read the request and evidence in the chat card. Use **Correct this location**,
then draw a rectangle around the target with the native markup tool.
Move or resize the region to adjust its saved location. **Inspect detail** increases zoom only when selected.
Native dimension callouts are located locally with pdfplumber.
A unique label matched to the review evidence can be highlighted at its native PDF coordinates.
Repeated or missing labels remain unmarked. These highlights identify dimension text;
they do not verify the associated geometry or engineering verdict. There are no placeholder notes at the page edge.
No drawing data is sent to an external extraction service.
Scanned pages without native text require a manually placed location in this version.
Old corrections keyed only by sequential issue numbers must be confirmed again.
Additional findings in historical reviews use the revised PDF location. An original location requires confirmation.

Use **Markup tool** to add highlights, drawing strokes, shapes, arrows, text, callouts, or notes.
**Undo** and **Redo** apply to saved drawing edits. Changes are stored separately from the source PDF.
Select **Export PDF** to download the active PDF with its review annotations.

The agent uses the same local text-location service and versioned edit commands as the viewer.
A review status or highlighted region does not certify engineering correctness.

### Local vision and bounded review

The drawing action uses the **Captioning LLM**, independently of the chat model.
Choose an installed vision-capable local model, such as `qwen3-vl:8b-instruct`, for that role.
New results show the vision model and the number of review passes for each finding.

The reviewer shows each comment finding as it becomes available. Comment verification has a five-minute time limit.
Each stage reports work it could not finish. Request extraction uses the marked original only.
Verification uses both revisions.
Extraction uncertainty receives verification before the reviewer decides that a request remains unclear.
Annotation close-ups supplement the full page when native annotation locations are available.
Numeric requests retain their associated supervisor value.
A different grounded revised value cannot receive a passing result.
Unclear results can receive up to three visual passes,
using the full page and overlapping crops within the review time limit.
A supported verdict can remain separate from an unresolved location. The review does not claim every issue is fixed.

Each new chat turn evaluates the drawings again. Repeated calls for the same PDF pair within one turn are blocked.

**Show in original** locates the native review comment when available. **Show in revised** uses revised-sheet evidence.
Page navigation does not wait for inference or saving. The attention ring is a temporary view effect.
It is not saved or exported as a PDF annotation.

The original-sheet action resolves native annotation comments independently of revised-sheet evidence.
The local locator also searches unique verbatim note excerpts, including finish instructions and BOM text.
A located excerpt is evidence text, not a measured feature. Ambiguous matches still require confirmation.
Native text-line indexing uses pdfplumber and reports explicit extraction limits.
